# 系统与平台规范

适用于 LSPosed 注入、系统窗口、任务交换、缩放与输入协作。系统层不是独立服务器，跨进程通信发生在 Android 系统组件之间。命名与切片测试约束见[项目结构与代码规范](项目结构与代码规范.md)，呈现规则见[界面与交互规范](界面与交互规范.md)。

## 进程与分层

| 进程 | 入口职责 | 边界 |
| --- | --- | --- |
| `android` | WMS / ATMS 任务、窗口变换、输入和旋转协作 | 在系统所属线程及锁范围内写入系统状态 |
| `com.android.systemui` | 工作区、TaskView、顶栏和交互 | 宿主组装功能组件，避免堆入新的独立业务 |
| `com.android.settings` | 系统设置中的模块入口 | 不承载任务或窗口业务 |
| `com.xiaomi.type`（可选） | 横屏输入法策略 | 仅在对应功能与配置范围内生效 |

所有 Java 源码共用 `io.github.zerohomers0.onesteplite` 包，仅按目录划分功能。`policy/` 保持无 Android 依赖的纯判定；反射兼容逻辑集中在 `platform/`。既有功能中的历史反射按相关改动逐步收敛，不为新功能复制。

## 任务身份与归属

- 同时校验 taskId、token、userId、displayId 和场景代次；taskId 可复用，不能单独作为所有权证明。
- 主窗、小窗、顶栏与原生自由窗口各有唯一当前归属。交接必须确认新归属后再清理旧绑定。
- 原生任务暂时不可见或从根任务列表消失，不等于应用死亡；结合 Shell、控制器和 token 判断。
- 移出工作区、退出顶栏应交还存活任务，不能用结束应用代替归属交接。
- 只放宽、裁剪或调整精确识别的工作区对象；其他应用和 OEM 窗口保留原生行为。

## 系统调用与事务

1. 系统状态写入使用对应 Handler / Shell executor，并在需要时持有 WMS 全局锁；失败不能改为任意线程直接写入。
2. 反射先检查能力和签名，异常进入明确的兼容或退出路径。不得忽略错误后宣称交接成功。
3. 提交回调使用 `SurfaceControl.TransactionCommittedListener`，不能向反射接口传入 `Runnable` 代替。
4. 事务身份跟随 merge / apply / close 管理。原生 Observer 的 finished 通知不是 compositor commit。
5. 改变父节点、矩阵、裁剪、透明度和输入元数据时明确资源所有者，退出、失败与取消都要恢复。
6. 媒体或任务 Binder 查询尽量在全局锁外完成；绘制回调保留必须逐帧重申的原生 Surface / 输入保护。

## 锁屏与恢复

`WindowState.getSurfaceControl()` 是父容器，窗口属性 alpha 作用于客户端缓冲区。解除临时隐藏时，父容器恢复自己的原生 alpha（缺少缓存时为 1），不能写回客户端的隐私 alpha=0，否则重新显示只更新子缓冲区时会留下整个工作区透明。

`RetainedWindow` 在息屏起始事务中持有主窗与已验证的工作区表面。`UnlockGeometryReplay` 保存确认几何，补齐提前生成的原生解锁 start / finish 事务；`UnlockFinishGate` 同时等待原生收尾提交和 Host 帧提交。

- 主窗、顶栏和侧栏在同一交接中恢复，不能先显示全屏内容后再缩放。
- 状态栏尺寸正确不能证明应用 Surface 正确；必须单独验证内容矩阵与原生收尾。
- 快速重新锁屏、退出或新场景使旧 ticket 失效；旧提交不得释放新场景的遮挡。
- 超时或能力缺失走隐藏清理／物理全屏恢复，不提前显示未经确认的工作区。

## 输入与层级

工作区窗口按 UID、session、包名、标题和类型识别，不只按标题或系统进程判断。外部窗口、截图预览与系统手势条不得误标为自有窗口。

`MainWindowClip` 在稳定 WindowToken 上约束状态栏和精确匹配的 DockAssistantView；后者同时由 `InputMagnificationPolicy` 精确纳入主窗缩放，不能只裁剪而假设其父层已缩放。原生自由窗口继续使用自身关闭、停靠和拖动逻辑。弹窗临时层级和灵动岛显示租约在关闭、重建和 detach 时恢复。

侧边手势裁剪在原生 `prepareSurfaces` 之后重申，不因 token 与尺寸未变而跳过；客户端隐藏后仍可能播放退出动画，不能以请求可见性为由提前停止保护。稳定状态栏保留裁剪去重，侧边手势重复重申不输出逐帧日志。

视频接入同时处理画面和输入：抑制原生视频命中区域时保存原状态，归还时重交输入元数据。接入区域以外的透明部分不能点击穿透到被覆盖的工作区控件。

## 通信与配置

### 内容拖曳的初始接入

`ShareWorkspace` 持有一次内容拖曳会话，`ContentPanel` 负责当前用户可访问的媒体、系统选择器选中文件与当前剪贴板。文件页显示 MediaStore.Files 中当前用户可访问的最近添加文件，按添加时间与 ID 降序，单次最多 60 项，排除图片、待写入与回收站项目，不扫描文件系统、不复制原文件。仅用户点击「更多文件」才调用 ACTION_OPEN_DOCUMENT，保留持久读取授权和 URI 记录。文件行只显示名称、类型、大小与添加时间，不读取文件内容或打开文件预览，长按进行拖曳分享。数据读取和缩略图在工作线程完成，关闭、分页切换和用户变化后的迟到结果不更新界面。用户可开启仅在工作区活跃时采集的文字历史（最多64条、非固定内容7天到期、跳过敏感标记），隐藏／锁屏／detach时撤销监听；不增加来源应用作用域。

顶栏投递携带具体分享组件，小窗投递限定接收包；已有小窗目标复用确认后的任务提升回调，仍须遵守场景与用户校验。媒体查询权限、外部 URI 转授、后台启动及侧栏实际 DROP 路由需要在对应 ROM 真机验证；当前系统拒绝转授时明确失败，不使用全局权限放宽。

原工作区根窗口负责转发拖曳开始与结束，确保普通顶栏被视频或横屏任务遮住时仍能开始分享会话。此时 `ShareRailOverlay` 仅在拖曳期间挂载一条 50dp 的 SYSTEM_UI_DIALOG 分享条，位于主窗上方，不调整视频、TaskView 或任务表面的所有权。拖曳结束立即移除视图和灵动岛借用；已接受的异步内容交付仅保留会话与短期能力，完成、超时、锁屏或宿主退出均撤销。没有新增隐藏周期查询。

来源内容补充采用两条显式路径：`TextDragActivity` 接收标准 ACTION_PROCESS_TEXT 的选区文字，清洗为纯文本后允许全局拖曳，不覆盖来源的选择操作、不回写文字；`SourceCaptureController` 仅按用户点击截取主窗的物理区域，在工作线程复用已有截图接口，拒绝不可截取场景。框选结果按最长1600px缩放，JPEG运输最多512KiB，经模块Provider解码尺寸和格式验证后进入原有有界临时区，取消、失效或未消费关闭时删除。本地位图、预览窗口及监听随场景关闭释放。两条路径均不新增来源应用钩子作用域，不提供通用应用控件提取或OCR；截取结果是画面图片，不能等同于原图文件。

`ContentPermissionBridge` 在 system_server 中仅扩展真实 DROP 所带权限 Binder：验证 SystemUI 调用者、原目标包、只读标志、当前缩放／未锁屏、同用户和原 URI 集合，将来源 UID 的有限读取委托给模块。能力绑定宿主死亡及60秒超时，跨用户 URI、任意路径和新增 URI 均拒绝。模块读取成功后复制进有界私有临时区，再以自己拥有的 URI 分享，不手动向目标包授予依赖 SystemUI 计时回收的长期权限。接口签名或来源能力不匹配时明确失败；真实 ROM 兼容待验收。

`ContentInboxProvider` 仅向模块和经过 UID 验证的 SystemUI 提供列表及一次性启动凭据。其他应用只可通过逐 URI 临时读取授权读取文件；不支持写入、路径枚举或任意文件路径。系统选择的文档由Provider代理打开原文档URI，不复制，文档记录不适用临时复制文件的24小时期限。补充入口收到的外部分享才采用有界复制：单文件最多100 MiB、临时文件总量200 MiB、记录最多128条、临时复制保留24小时，过期清理由访问事件触发。`ContentImportActivity` 接收系统选择／外部分享与可信凭据，复制前后校验、失败删除部分文件；凭据在30秒内只能消费一次。可见代理启动目标，由系统管理目标 Activity 的读取授权，不能将页面启动成功等同于发送成功。

- 校验调用者 UID、权限和所有权 Binder；广播和 Intent 的内容不能自行证明可信身份。
- 设置写入走 `WorkspaceSettingsProvider`，宿主通过 `WorkspaceSettingsClient` 重读；按请求代次丢弃迟到结果。
- 跨进程消息携带场景、请求或会话身份，幂等处理重复、延迟和乱序消息。
- 正常关闭和 Binder 死亡都要解除监听、撤销计时、归还窗口并释放句柄。

## 性能与诊断

### 拖曳操作与交付回执

`ShareActions` 仅包含固定内置操作，不导入 HyperCopy 代码、远程规则或可配置匹配规则。地图使用公开 `geo:` 查询，搜索使用 `ACTION_WEB_SEARCH`，翻译使用 `ACTION_TRANSLATE`；无处理应用时由已安装浏览器处理编码后的 HTTPS 地址。笔记、图片编辑和用户选择的图片搜索入口仅使用公开 Intent。入口与图标查询在既有工作线程执行，不在位置回调中查询安装列表。

`ShareDelivery` 的一次性 Binder 回执只接受本用户模块 UID：系统接受 DROP 后保留交付会话，模块完成读取并成功启动接收页面后回执成功；失败返回模块拥有的 URI 或纯文字供重试。回执只证明接收页面启动，不证明用户最终发送。代次、工作区退出、60秒超时与锁屏取消后，迟到代理不得继续启动应用。外部读取能力继续由真实 DROP 委托，未读取成功的原始 URI 不长期保留。

`ContentShelfStore` 复用已有私有临时区，最多64项、总记录128项，暂存原有条目不重复计数；文本按全文去重，外部文件先通过原有有界复制取得所有权。移除仅清除暂存标记，已授权内容保留原有效期；暂存项不执行分享后10分钟清理，但仍受24小时临时区期限约束。系统最近文件仍直接读取 MediaStore，暂存不替换文件页。

会话入口经 `EditorPasteCompat` 的认证中继在系统进程查询应用公开的 sharing shortcuts，最多32项，仅当前用户、启用且导出接收组件。通过标准 `EXTRA_SHORTCUT_ID` 传递会话身份，不猜测聊天界面、读取联系人或增加来源应用作用域；应用未公开或系统不允许查询时只保留普通分享入口。原生多项文字／图片影子保持所有原始 ClipData 项、顺序与授权载荷，不将摘要替代正文。

顶栏两类配置由模块的 `ShortcutSettingsStore` 分开保存，设置页与 SystemUI 编辑器通过受验证的 `WorkspaceSettingsProvider` 调用读写同一份配置。仅模块自身、系统 UID 与 SystemUI 可访问，且不得跨用户读取或覆盖；快捷应用跨用户旧路径继续使用原本的 Secure 设置。未保存过的类别读取原有 Secure 值，显式保存空列表与从未保存保持区别。设置页后台查询与保存、返回或配置重建后丢弃旧回调，重建保留当前选择；设置页每次开关和排序串行即时写入，返回不取消已提交的保存。保存通知复用设置事件，活跃工作区刷新快捷应用，分享入口在下一次拖曳查询时读取，不增加隐藏状态的查询或周期调度。

开机预热由 LSPosed 的 SystemUI 入口触发，等待用户解锁与原生工厂就绪。`TaskViewWarmup` 最多准备五个未挂载 TaskView，按用户、工厂和资源配置复用；不添加工作区窗口、不启动应用、不创建真实应用任务、不开启心跳。首次使用后不补货，迟到回调和不兼容缓存释放；原生构造前持久化本次开机尝试，SystemUI 同一次开机重启后不重试，避免崩溃循环。第三方应用本身的冷启动不能通过预热空容器消除。

| 工作 | 正常路径 | 兜底与停止条件 |
| --- | --- | --- |
| 已打开应用标记 | 合并任务、转场、可见性事件 | 30 秒；隐藏／锁屏／detach 停止 |
| 媒体状态 | 活跃会话及播放状态回调 | 15 秒；回调不可用时 2 秒，Host 失效后停止 |
| 主窗租约 | 动画或几何变化时即时发布 | 8 秒续租，15 秒失联恢复，退出／锁屏停止 |
| 小窗表面 | 原生任务与转场回调 | 30 秒完整补偿，过渡期间不争夺变换 |
| 常规诊断 | 首次与变化时输出 | 相同文本 30 秒限频，最多缓存 128 项 |

相同稳态缩放文件只更新租约时间；内容变化、动画或文件异常仍使用 AtomicFile。广播、设置与文件通道独立，不能因一个通道失败而抑制退出命令。
错误与生命周期日志不被常规限频吞掉。日志不包含密钥、个人消息或凭据；真机功耗结论须区分模块开销与共享系统进程、媒体播放、USB 调试的影响。

## 验证与发布

### 剪贴板点击粘贴

`EditorPasteCompat` 安装在 system_server 的输入法服务中，按解锁与输入启动事件注册模块内中继，不进行周期查询。内容面板为非焦点窗口，保留原编辑器焦点；单击剪贴板文字才查询并提交短时快照。提交必须同时匹配用户、客户端 UID、输入框 ID、连接 Binder 与可见焦点窗口 token；锁屏、工作区退出、焦点变化及过期请求均拒绝。键事件指定显示和目标 UID，不向不明目标发送粘贴；不增加来源应用作用域。系统拒绝时打开选词页。此操作会将所选记录写入系统剪贴板；输入事件提交成功仅表示系统接受事件，具体编辑器是否处理仍需真机验收。

### 可选系统提取桥接

`SystemExtractHooks` 在 `com.miui.contentcatcher` 中接收提取结果，校验原始 Binder 调用者与来源 token 的包名一致后，再清除调用身份并提交会话。它绕过传送门服务和界面；`PortalHooks` 另在 `com.miui.contentextension` 中适配内容回调作为兼容路径。两者仅在成功接管后阻止重复处理。来源应用不增加模块作用域，也不修改 AES APK 或全局传送门开关；部分 ROM 的提取初始化仍受该开关及安装状态影响，所以不能将此称为所有 ROM 都支持的通用提取器。手动截取主窗图片可独立于传送门工作。

选词由自有 `WordSelectionPane` 使用 Android ICU 完成，不调用 OEM 选词界面，不加载第三方 GPL 实现。词块支持点选、横向滑动连选、全选、拆字及长按选区拖曳；原文范围保留连续选区中的空格、标点和 Unicode 字符。词块数量有界，超出上限的尾部保留为一个整体，避免静默丢失文字。

`PortalRelay` 按 Binder 调用 UID、包名及用户验证两端，SystemUI 注册会话 Binder，两个系统提取入口只可查询和提交当前会话。图片经大小和像素限制写入模块受控内容库；调用者传入的 URI 不直接转发。跨进程调用不持有注册锁。

SystemUI 只在工作区活跃时观察真实输入，不注入合成触摸；隐藏、锁屏、detach 和配置变更时释放观察器、临时源窗口和选词面板。接管需匹配同次按下、当前用户、主窗区域及短期请求时效。单指图片原生交接只允许经过窗口身份验证的临时源窗口，从同用户、同来源包的可见全屏焦点窗口转移触摸；接口或校验失败时保持 OEM 路径。双指提取的图片进入自有图片预览，之后通过新的单指长按拖曳，避免把两指手势错误移交给原生单指拖曳；文字仍进入自有选词面板。

文字选词后使用面板自身收到的长按启动标准全局拖曳。离线策略及 WM 替身检查不代表原生输入交接已在真机生效，需启用可选作用域并重载后分别验证文字、图片、取消、锁屏与后台恢复。

图片识字使用独立的 `ImageTextRequest` 连接 AICR V2，经 `OcrWire` 和有界 Parcel 读取器获得文字，不加载传送门代码。只有用户点击识字或投递到识字入口时才解码、绑定服务；请求拥有临时读权限、位图、绑定和超时，关闭面板即取消 UI 回调并释放绑定与读权限。进程最多运行一次识字；Binder 超时只结束 UI 等待，不能伪称已经中断远端识别，旧工作线程退役前不再启动新识别。系统引擎缺失或不兼容时提示失败，保留图片分享；不自动联网识字或下载模型。

拖曳卡片触点位于底部，箭头露在手指上方。模块发起的 ClipDescription 带有有界的箭头偏移量；顶栏拖曳期间才挂载透明 `ShareDragCatchment`，将分享栏可接收区域向下延伸，并以箭头坐标判定入口。它不绘制第二套顶栏、不改立方体动画，不修改全局 WMS 坐标或其他应用拖曳；结束、取消、锁屏和 detach 立即移除。普通外部拖曳没有该标记，继续使用原始触点。

`NativeContentDragCard` 在工作区缩放活跃且未锁屏时统一适配同用户、同显示、可见全屏来源窗口的单条原生纯文字或图片全局拖曳。核对真实窗口 Binder、所有者 UID 与任务模式，拒绝安全窗口、SystemUI／模块自有来源和不支持的载荷。图片只复制来源已有的拖曳影子：临时镜像放在经过检查、未绑定任何显示的层栈，最多采样512×512像素，拒绝安全内容并立即移除镜像、释放硬件缓冲；不显示、重挂或修改原影子，不读取原图 URI。替代影子与原生会话同寿命，失败保留原样；原载荷、权限和来源输入保持不变，不增加来源应用作用域。卡片玻璃只对当前数据与表面身份匹配的会话设置有界模糊区域。当前入口签名兼容13参数的 `performDrag`，其他签名保持原行为。

箭头命中使用描述中的影子触点和箭头间距，结合 DragEvent 的真实影子偏移调整来源缩放比例；异常值和旧接口回退到有界声明值。命中区域收紧到图标视觉区域。单指系统文字提取延迟至同次按下满3秒，抬手、取消、移动超出触摸阈值、场景变化或隐藏时撤销；显式双指提取不延迟。原应用自己的菜单时长不被重写。

「分享后清理临时图片」默认关闭，只标记本模块生成的图片。目标 Activity 成功启动后才设置10分钟读取宽限期，到期由下一次内容库访问清理；启动成功不是最终发送成功。系统文件引用、导入文件与相册原图不使用此清理规则。关闭选项会在内容库访问时撤销待清理标记，原有24小时临时区保留规则不变。

开机壁纸缓存包含完成材质处理的底图和小尺寸圆井模糊图。工作区首次创建时同步转移这两个现成位图的所有权并铺底，再开始进入动画；没有命中时保持原异步获取路径。主线程不新增截图或模糊计算，使用后不补货，不新增隐藏渲染、真实应用启动或心跳。手势指定的本次主窗方向优先于已保存的位置，保留场景恢复也遵守这一规则。

本地与 CI 执行同一套 `:app:lintRelease :app:stageRelease` 和 `test.ps1`，包校验只用 `tools/assert_module_apk.py`。新增生产依赖逐个补入受影响套件的 javac 源列表，并核对 `checks=` 的变化。

`version.json` 是版本信息的唯一来源。发布版本码递增，签名私钥留在本地忽略目录或仓库 Secrets；正式 tag 必须生成签名 APK 和 SHA-256 校验文件。发布前确认源码、tag、CI 产物与 Release 指向同一个提交，真机验证范围如实记录。

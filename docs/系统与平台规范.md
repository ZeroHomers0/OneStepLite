# 系统与平台规范

适用于 LSPosed 注入、系统窗口、任务交换、缩放与输入协作。系统层不是独立服务器，跨进程通信发生在 Android 系统组件之间。命名与切片测试约束见[项目结构与代码规范](项目结构与代码规范.md)，呈现规则见[界面与交互规范](界面与交互规范.md)。

## 进程与分层

| 进程 | 入口职责 | 边界 |
| --- | --- | --- |
| `android` | WMS / ATMS 任务、窗口变换、输入和旋转协作 | 在系统所属线程及锁范围内写入系统状态 |
| `com.android.systemui` | 工作区、TaskView、顶栏和交互 | 宿主组装功能组件，避免堆入新的独立业务 |
| `com.android.settings` | 系统设置中的模块入口 | 不承载任务或窗口业务 |
| 小米内容提取服务、传送门 | 适配 OEM 原本就提供的文字与图片 | 经鉴权中继进入当前工作区手势 |
| 已启用作用域的应用进程 | 读取命中标准控件与虚拟语义节点 | 仅在符合条件的来源窗口和手势内提取 |
| 小米输入法（可选） | 小米输入法横屏策略 | 按需启用 |

SystemUI 工作区以 `WorkspaceHost` 作为编排入口：显示采样、壁纸资源、侧栏行序、格子表面、裁剪/触摸区域和退出保留回收与恢复确认和任务启动各自有单一所有者；60 秒隐藏回收计时不得在宿主与控制器各存一份。跨控制器调用只传场景、槽位和所有权票据，不复制 Surface 生命周期或另建第二套调度。

所有 Java 源码共用 `io.github.zerohomers0.onesteplite` 包，仅按目录划分功能。`contract/` 只保存跨进程动作、字段、缩放协议和不可变信号，不得引用 Android 或 Xposed；调用方自行负责 Intent/Bundle 包装。`policy/` 保持无 Android 依赖的纯判定。`systemui/platform/` 只保留 `*Hooks` 或 `Native*` 边界类型，场景控制器和流程编排位于 `systemui/workspace/`。反射兼容逻辑集中在 `platform/`。既有功能中的历史反射按相关改动逐步收敛，不为新功能复制。

## 任务身份与归属

- 同时校验 taskId、token、userId、displayId 和场景代次。taskId 可复用，不能单独作为所有权证明。
- 主窗、小窗、顶栏与原生自由窗口各有唯一当前归属。交接必须确认新归属后再清理旧绑定。
- 原生任务暂时不可见或从根任务列表消失，不等于应用死亡。结合 Shell、控制器和 token 判断。
- 移出工作区、退出顶栏应交还存活任务，不能用结束应用代替归属交接。
- 只放宽、裁剪或调整精确识别的工作区对象。其他应用和 OEM 窗口保留原生行为。

## 系统调用与事务

1. 系统状态写入使用对应 Handler / Shell executor，并在需要时持有 WMS 全局锁。失败不能改为任意线程直接写入。
2. 反射先检查能力和签名，异常进入明确的兼容或退出路径。不得忽略错误后宣称交接成功。新增 Hook 组通过 `HookGuard` 事务安装，必需目标缺失时撤销本组回调；可选探测必须显式记录跳过原因。
3. 提交回调使用 `SurfaceControl.TransactionCommittedListener`，不能向反射接口传入 `Runnable` 代替。
4. 事务身份跟随 merge / apply / close 管理。原生 Observer 的 finished 通知不是 compositor commit。
5. 改变父节点、矩阵、裁剪、透明度和输入元数据时明确资源所有者，退出、失败与取消都要恢复。
6. 媒体或任务 Binder 查询尽量在全局锁外完成。绘制回调保留必须逐帧重申的原生 Surface / 输入保护。

## 锁屏与恢复

`WindowState.getSurfaceControl()` 是父容器，窗口属性 alpha 作用于客户端缓冲区。解除临时隐藏时，父容器恢复自己的原生 alpha（缺少缓存时为 1），不能写回客户端的隐私 alpha=0，否则重新显示只更新子缓冲区时会留下整个工作区透明。

`RetainedWindow` 在息屏起始事务中持有主窗与已验证的工作区表面。`UnlockGeometryReplay` 保存确认几何，补齐提前生成的原生解锁 start / finish 事务。`UnlockFinishGate` 同时等待原生收尾提交和 Host 帧提交。

- 主窗、顶栏和侧栏在同一交接中恢复，不能先显示全屏内容后再缩放。
- 状态栏尺寸正确不能证明应用 Surface 正确。必须单独验证内容矩阵与原生收尾。
- 快速重新锁屏、退出或新场景使旧 ticket 失效。旧提交不得释放新场景的遮挡。
- 超时或能力缺失走隐藏清理／物理全屏恢复，不提前显示未经确认的工作区。

## 输入与层级

工作区窗口按 UID、session、包名、标题和类型识别，不只按标题或系统进程判断。外部窗口、截图预览与系统手势条不得误标为自有窗口。

`MainWindowClip` 在稳定 WindowToken 上约束状态栏和精确匹配的 DockAssistantView。后者同时由 `InputMagnificationPolicy` 精确纳入主窗缩放，不能只裁剪而假设其父层已缩放。原生自由窗口继续使用自身关闭、停靠和拖动逻辑。弹窗临时层级和灵动岛显示租约在关闭、重建和 detach 时恢复。

侧边手势裁剪在原生 `prepareSurfaces` 之后重申，不因 token 与尺寸未变而跳过。客户端隐藏后仍可能播放退出动画，不能以请求可见性为由提前停止保护。稳定状态栏保留裁剪去重，侧边手势重复重申不输出逐帧日志。

视频接入同时处理画面和输入：抑制原生视频命中区域时保存原状态，归还时重交输入元数据。接入区域以外的透明部分不能点击穿透到被覆盖的工作区控件。

## 工作区换边与小窗换位

- 主小窗切换和按钮换边都保留实际任务，交接期间由过渡会话保护输入。置顶安置在目标逻辑尺寸和画面就绪后淡入。等待期间原生开始及收尾事务也要保持遮挡。
- 小窗拖动换位使用宿主内部拖曳身份，核对场景、原槽、任务代次、控制器和目标绑定。固定布局移动原 SurfaceView，双方表面均有效时才做成对动画，结束后同帧提交布局和恢复背景。滚动布局由 `SideRowOrder` 交换逻辑行，再按原位置偏移过渡。两条路径均保留原任务、控制器和绑定。
- 普通小窗按实际槽位像素 bounds 和等比缩放后的 `densityDpi` 渲染，主窗继续使用系统显示缩放，TOP 使用自己的逻辑视口。任务交接、收藏、Home 提升和回滚必须在同一原生事务中同时提交 bounds 与密度；稳态小窗矩阵为 1:1，不能继续保留全屏应用缓冲区再逐帧缩小。
- 动画期间的输入保护和顶栏的视觉可用状态独立。手机顶栏允许横屏页面及识别到的导航应用手动置顶。竖屏导航使用居中视口，窗口资源尺寸、表面和原生触摸映射使用相同逻辑边界。手动换边和随应用换边保持当前外观，完成后重新检查主窗置顶条件。旧回调不得改变新场景。
- 工作区进入和退出复用跨进程单调时钟。物理坐标的壁纸托底覆盖让出的区域，退出时等全屏事务提交后释放。不得额外给 SurfaceView 父层叠加同一位移。
- 进入息屏事务时即隐藏已验证的宿主、镜像和过渡表面。恢复前保持遮挡，只有 Host 帧和原生解锁收尾均确认时恢复当前 alpha。较新的退出、换边或锁屏代次可否决旧提交。
- 原生层级调整只用于验证过的自有窗口。截图动画与弹窗共存时借用的相对层级及灵动岛显示状态，在关闭、重建或 detach 后归还。


## 设置与跨进程通信

- 校验调用者 UID、权限和所有权 Binder。广播和 Intent 的内容不能自行证明可信身份。
- 设置写入走 `WorkspaceSettingsProvider`，宿主通过 `WorkspaceSettingsClient` 重读。按请求代次丢弃迟到结果。设置变更广播使用模块签名权限，发送端和接收端都必须理解广播只是唤醒信号，权威数据仍从 Provider 读取。
- 跨进程消息携带场景、请求或会话身份，幂等处理重复、延迟和乱序消息。
- 正常关闭和 Binder 死亡都要解除监听、撤销计时、归还窗口并释放句柄。

顶栏两类配置由模块的 `ShortcutSettingsStore` 分开保存，设置页与 SystemUI 编辑器通过受验证的 `WorkspaceSettingsProvider` 调用读写同一份配置。仅模块自身、系统 UID 与 SystemUI 可访问，且不得跨用户读取或覆盖。快捷应用跨用户旧路径继续使用原本的 Secure 设置。未保存过的类别读取原有 Secure 值，显式保存空列表与从未保存保持区别。设置页后台查询与保存、返回或配置重建后丢弃旧回调，重建保留当前选择。设置页每次开关和排序串行即时写入，返回不取消已提交的保存。保存通知复用设置事件，活跃工作区刷新快捷应用，分享入口在下一次拖曳查询时读取，不增加隐藏状态的查询或周期调度。

## 内容来源、权限与临时存储

`ShareWorkspace` 持有一次内容拖曳会话，`ContentPanel` 负责当前用户可访问的媒体、系统选择器选中文件与当前剪贴板。文件页显示 MediaStore.Files 中当前用户可访问的最近添加文件，按添加时间与 ID 降序，单次最多 60 项，排除图片、待写入与回收站项目，不扫描文件系统、不复制原文件。仅用户点击「更多文件」才调用 ACTION_OPEN_DOCUMENT，保留持久读取授权和 URI 记录。文件行只显示名称、类型、大小与添加时间，不读取文件内容或打开文件预览，长按进行拖曳分享。数据读取和缩略图在工作线程完成，关闭、分页切换和用户变化后的迟到结果不更新界面。文字历史固定在工作区活跃时采集（最多64条、非固定内容7天到期、跳过敏感标记和 URI），不提供手动开关，隐藏／锁屏／detach时撤销监听。不增加来源应用作用域。

来源内容补充采用两条显式路径：`TextDragActivity` 接收标准 ACTION_PROCESS_TEXT 的选区文字，清洗为纯文本后允许全局拖曳，不覆盖来源的选择操作、不回写文字。`SourceCaptureController` 处理用户主动框选及双指识字的主窗物理区域，在工作线程复用已有截图接口，拒绝不可截取场景。框选结果按最长1600px缩放，JPEG运输最多512KiB，经模块Provider验证尺寸和格式后写入独立的短生命周期拖曳缓存。双指识字裁去状态栏后直接使用有界内存位图。取消、失效或未消费关闭时清理临时文件、位图和监听。

应用图片提取使用独立拖曳缓存：UUID 文件、最多64项/256MiB，正常10分钟过期，超出上限自动淘汰最旧项，取消、失败和过期时删除。该缓存不属于内容区普通记录，不使用128条记录或8条捕获预留限制；长按提取因此不会被长期暂存内容占满阻断。原生拖曳直接交付模块拖曳缓存 URI，由平台负责按实际 DROP 转授读取权限。微信发图使用分享栏的应用分享入口。仅模块代投需要时，才会发布 `Pictures/.OneStep` 的短生命周期 MediaStore 副本，失败、取消或过期时回收。内容面板排除该目录、待写入和回收站项目。内容区仍保留普通记录和捕获预留，用于用户明确暂存或导入的内容，并在容量不足时按“已从暂存移除的底稿、旧捕获预留、最旧未暂存普通内容”顺序回收。

`ContentPermissionBridge` 在 system_server 中仅扩展真实 DROP 所带权限 Binder：验证 SystemUI 调用者、原目标包、只读标志、当前缩放／未锁屏、同用户和原 URI 集合，将来源 UID 的有限读取委托给模块。能力绑定宿主死亡及60秒超时，跨用户 URI、任意路径和新增 URI 均拒绝。模块读取成功后复制进有界私有临时区，再以自己拥有的 URI 分享，不手动向目标包授予依赖 SystemUI 计时回收的长期权限。接口签名或来源能力不匹配时明确失败。真实 ROM 兼容待验收。

`ContentInboxProvider` 仅向模块和经过 UID 验证的 SystemUI 提供列表及一次性启动凭据。其他应用只可通过逐 URI 临时读取授权读取文件。不支持写入、路径枚举或任意文件路径。系统选择的文档由Provider代理打开原文档URI，不复制，文档记录不适用临时复制文件的24小时期限。补充入口收到的外部分享才采用有界复制：单文件最多 100 MiB、临时文件总量 200 MiB、记录最多 128 条、临时复制默认保留 24 小时，过期清理由访问事件触发。达到上限时，新导入先完成有界复制，再由 Provider 统一回收最旧未暂存记录；无法回收时删除本次部分文件并明确报告容量不足。外部拖拽投递优先复制到独立拖曳缓存，不再写入普通内容区；只有用户明确“暂存”时才提升为内容区记录。`ContentImportActivity` 接收系统选择／外部分享与可信凭据，复制前后校验、失败删除部分文件。凭据在30秒内只能消费一次。可见代理启动目标，由系统管理目标 Activity 的读取授权，不能将页面启动成功等同于发送成功。

`ContentShelfStore` 复用已有私有临时区，最多 64 个暂存项，普通记录上限 128 项，捕获预留单独计数。暂存原有条目不重复计数。文本按全文去重，外部文件先通过原有有界复制取得所有权。移除仅清除暂存标记；容量不足时这些已移除底稿优先回收，未移除的暂存项不自动回收。暂存项不执行分享后 10 分钟清理，但仍受 24 小时临时区期限约束。系统最近文件仍直接读取 MediaStore，暂存不替换文件页。

应用提取与外部拖拽缓存固定使用10分钟保留期，取消、失败或过期即删除，不受内容区保留开关影响。内容区中本模块生成的图片仍按「分享后清理临时图片」处理：默认保留24小时，开启后目标 Activity 成功启动时设置10分钟读取宽限期。启动成功不是最终发送成功。系统文件引用、导入文件与相册原图不使用此清理规则；关闭选项会在内容库访问时撤销待清理标记。

文件分享前在工作线程核对模块拥有的 URI 和可读性。图片仅解码有界头部以校正 MIME、显示文件名和扩展名，不重编码原文件。`EXTRA_STREAM`、`ClipData` 与 Intent 类型使用同一组校正结果。元数据同步持久化完成后才交付。接收方打开代理系统文档时仅在原文档读取范围切换为模块身份并最终恢复，使用模块既有持久读取授权。来源临时授权在有界复制及元数据提交完成后释放，取消和销毁使用同一幂等释放入口。不将来源授权扩展到接收方，也不提前删除交付后的模块副本。

## 应用内提取与识字

`EditorPasteCompat` 安装在 system_server 的输入法服务中，按解锁与输入启动事件注册模块内中继，不进行周期查询。内容面板为非焦点窗口，保留原编辑器焦点。单击剪贴板文字才查询并提交短时快照。提交必须同时匹配用户、客户端 UID、输入框 ID、连接 Binder 与可见焦点窗口 token。锁屏、工作区退出、焦点变化及过期请求均拒绝。键事件指定显示和目标 UID，不向不明目标发送粘贴。不增加来源应用作用域。系统拒绝时打开选词页。此操作会将所选记录写入系统剪贴板。输入事件提交成功仅表示系统接受事件，具体编辑器是否处理仍需真机验收。

`SystemExtractHooks` 在 `com.miui.contentcatcher` 中接收提取结果，校验原始 Binder 调用者与来源 token 的包名一致后，再清除调用身份并提交会话。它绕过传送门服务和界面。`PortalHooks` 另在 `com.miui.contentextension` 中适配内容回调作为兼容路径。两者仅在成功接管后阻止重复处理。这两条 OEM 路径无需来源应用作用域，也不修改 AES APK 或全局传送门开关。部分 ROM 的提取初始化仍受该开关及安装状态影响。手动截取主窗图片可独立于传送门工作。

应用控件提取使用独立可选作用域。在已启用模块的应用进程中观察 Activity 触摸，长按时按当前触点命中控件。标准图片控件使用当前 Drawable，声明 ImageView 无障碍角色的自绘叶子可尝试渲染，保留已有自绘图片兼容入口。标准非编辑 TextView 优先读取有效选区，否则只取命中控件的文字。跳过安全窗口和标记敏感的控件。中继核验调用 UID、包名、用户、焦点主任务和工作区手势，原触摸继续交给来源应用。取得的图片可能是缩略图。

标准控件未命中时，在触点所在控件的虚拟无障碍节点中查找有效选区、可见叶子文字或明确标记的图片。按触点裁剪节点边界，跳过可编辑、密码和敏感节点。虚拟图片仅复制来源应用窗口内的节点区域，异步返回后复核节点边界和来源手势，所得图片为当前画面。单指提起文字需要越过 1.5 倍系统触摸滑动阈值，图片及区域候选使用系统阈值。长按前的滚动取消仍使用系统阈值。双指截图识字从主窗截取范围排除状态栏区域，手动框选沿用原范围。

提取结果按有界列表遍历，单项格式无效或交接被拒绝不得提前终止后续候选。解析接受已知 `viewContent` / `viewBitmap` 及有界的 `pick_mode` / `image_pick_mode` 包装。配置文字作为兜底，仅使用来源包一致的 Bundle 在 `apkParamList` 明确声明的 `miuiCE_` 文字字段，保留原文。逐项解析先写局部 Bundle，成功后才合入会话。不得猜测任意键、解引用来源 URI 或从对象字符串推断内容。

传送门已有图片位图时可在 `onPickImage` 执行前提交。若传送门在方法内才取得图片，仅接收同线程、同一次调用内成功写入 `setBitmap` 的位图，并沿用进入方法时的手势快照。在支持的 ROM 上，模块在同次请求的侧栏任务入队前提交位图。单指候选被宿主接受时，只跳过这次任务的图片侧栏入口。拒绝、双指或接口缺失时沿用原有流程。模块不读取传送门静态图片缓存，也不自行加载来源图片地址。

传送门的文本回调沿用传送门对独立「图片」占位结果的过滤。应用原生拖曳和标准选区入口仍交付应用提供的原文。

已知提取结果可携带 `view_rect` 和 `touch_points`。只有上报触点与同次实际按下接近、矩形位于当前主窗内时才使用边界，避免不同 ROM 的坐标空间误拒正常载荷。图片位图仅在确认完全透明时丢弃，保留有可见像素的图片。没有可用位图但具有匹配区域时，单指做出提起动作可进入预选区域的截图确认页。需要点击「使用选区」，并沿用安全图层拒绝及帧尺寸校验。区域候选低于真实图片，系统直接提取的区域提示不会阻止 OEM 后续取图。

应用原生全局拖曳开始后取消尚未启动的提取候选。同一次单指手势中的候选按内容提取服务图片、传送门图片、应用控件图片、标准控件真实选区、内容提取服务文字、传送门文字、应用控件普通文字和区域截图排序。兼容图片和应用控件普通文字为更高优先级候选额外等候 120 毫秒，按下代次、移动门槛与松手取消规则仍适用。确认单指移动后尝试直接提起图片或文字，交接失败提示重试。应用已选中的部分文字也可通过原生拖曳或标准选区菜单交付。双指截图识字结果仅在同一代次且尚未打开选词或预览时交付。

选词由自有 `WordSelectionPane` 使用 Android ICU 完成，不调用 OEM 选词界面，不加载第三方 GPL 实现。词块支持点选、横向滑动连选、全选、拆字及长按选区拖曳。原文范围保留连续选区中的空格、标点和 Unicode 字符。词块数量有界，超出上限的尾部保留为一个整体，避免静默丢失文字。

`PortalRelay` 按 Binder 调用 UID、包名及用户验证两端，SystemUI 注册会话 Binder，两个系统提取入口只可查询和提交当前会话。图片经大小和像素限制写入模块受控内容库。调用者传入的 URI 不直接转发。跨进程调用不持有注册锁。

SystemUI 只在工作区活跃时观察真实输入，不注入合成触摸。隐藏、锁屏、detach 和配置变更时释放观察器、临时源窗口和选词面板。接管需匹配同次按下、当前用户、主窗区域及短期请求时效。单指文字和图片都通过已校验的临时源窗口启动原生拖曳。输入转移优先采用同一显示、同一次按下、同设备和同指针的实际来源窗口。接触点落在应用子窗口时，只有子窗口和父窗口同包、同 UID、同任务、可见且没有安全标记，才使用子窗口的实际输入通道。接收候选前校验失败时保留 OEM 路径。双指提取的图片进入自有图片预览，之后通过新的单指长按拖曳，避免把两指手势错误移交给原生单指拖曳。文字仍进入自有选词面板。

文字选词后使用面板自身收到的长按启动标准全局拖曳。离线策略及 WM 替身检查不代表原生输入交接已在真机生效，需启用「内容提取服务」和「传送门」推荐作用域并重载后分别验证文字、图片、取消、锁屏与后台恢复。

图片识字使用独立的 `ImageTextRequest` 连接 AICR V2，经 `OcrWire` 和有界 Parcel 读取器获得文字，不加载传送门代码。只有用户点击识字或投递到识字入口时才解码、绑定服务。请求拥有临时读权限、位图、绑定和超时，关闭面板即取消 UI 回调并释放绑定与读权限。进程最多运行一次识字。Binder 超时只结束 UI 等待，不能伪称已经中断远端识别，旧工作线程退役前不再启动新识别。系统引擎缺失或不兼容时提示失败，保留图片分享。不自动联网识字或下载模型。

箭头命中使用自绘卡片声明的物理间距，不使用可能仍含来源应用兼容缩放的 DragEvent 私有偏移。命中区域保持图标视觉范围。单指系统提取先保留有界候选，达到系统长按阈值加150毫秒且明确移动后才转交原生拖曳。原地松手取消候选，抬手、场景变化或隐藏时释放。图片视图提取使用单次租约与5秒看门狗；迟到的 PixelCopy、编码或提交结果不能清除新的租约，超时回收未完成的语义图片预览，避免一次未回调的提取永久阻塞后续图片长按。文字提取不共享该图片租约。双指原生提取直接进入选词，900毫秒稳定双指停留后可用主窗截图和既有 AICR 识字兜底。捏合、移动、任一手指抬起或已有提取结果取消待执行截图。应用原有长按菜单时长不被改写，没有匹配的来源触摸快照时沿用焦点校验。焦点为来源应用的子窗口菜单时，仅可尝试使用通过同一身份校验的父窗口。临时来源窗口最多等待八帧建立有效 Surface，期间只更新同一次按下的指针位置，松手或取消立即退役。单指明确提起时，已取得的文字或图片优先交给原生拖曳，区域截图候选只在没有真实载荷时使用。单指交接失败提示重试。诊断额外记录系统实际转移触摸流的返回结果。 首次转移被拒后，仅在同一次按下尚有效时尝试已核验的同应用、同 UID、同任务父窗或焦点窗。图片原生拖曳启动被拒时可在下一帧再试一次，抬手、代次变化或锁屏立即取消。

系统语义提取的 `viewContent` 不是应用选区协议，不能标称为已经取得自定义阅读器的准确选区。已选文字优先使用应用原生拖放或标准 `ACTION_PROCESS_TEXT` 菜单。未提供该菜单的应用可由用户显式复制，再从内容面板剪贴板拖曳。不得用重新长按所得整页文字冒充前一选区，也不通过合成点击复制菜单来猜测选区。

## 拖曳输入与命中坐标

原工作区根窗口负责转发拖曳开始与结束，确保普通顶栏被视频或横屏任务遮住时仍能开始分享会话。此时 `ShareRailOverlay` 仅在拖曳期间挂载一条 52dp 的 SYSTEM_UI_DIALOG 分享条，位于主窗上方，不调整视频、TaskView 或任务表面的所有权。拖曳结束立即移除视图和灵动岛借用。已接受的异步内容交付仅保留会话与短期能力，完成、超时、锁屏或宿主退出均撤销。没有新增隐藏周期查询。

拖曳卡片触点位于底部，箭头露在手指上方。模块发起的 ClipDescription 带有有界的箭头偏移量。顶栏拖曳期间才挂载透明 `ShareDragCatchment`，将分享栏可接收区域向下延伸，并以箭头坐标判定入口。它不绘制第二套顶栏、不改立方体动画，不修改全局 WMS 坐标或其他应用拖曳。结束、取消、锁屏和 detach 立即移除。普通外部拖曳没有该标记，继续使用原始触点。

转发到独立分享栏的拖曳事件携带原接收视图，位置换算仍以原窗口为准。根窗口转入透明承接窗时保留选中状态。手指位于小窗时仍按箭头位置判定分享入口，松手先计算箭头命中，再按稳定的小窗任务身份回退投递。同来源取消只适用于小窗回退。迟到的结束回调按代次隔离，独立分享栏随会话退场，已接受的异步投递按自身回执结束。每次投递使用独立的临时代理任务处理一次性凭据，避免复用已存在的导入或投递页面。进程日志区分接受松手、凭据准备、代理启动与投递失败。

`NativeContentDragCard` 在工作区缩放活跃且未锁屏时统一适配同用户、同显示、可见全屏来源窗口的有界多条原生纯文字或图片全局拖曳。核对真实窗口 Binder、所有者 UID 与任务模式，拒绝安全窗口、SystemUI／模块自有来源和不支持的载荷。图片只复制来源已有的拖曳影子：临时镜像放在经过检查、未绑定任何显示的层栈，最多采样512×512像素，拒绝安全内容并立即移除镜像、释放硬件缓冲。不显示、重挂或修改原影子，不读取原图 URI。替代影子与原生会话同寿命，失败保留原样。原载荷、权限和来源输入保持不变，不增加来源应用作用域。卡片玻璃只对当前数据与表面身份匹配的会话设置有界模糊区域。入口适配见本节的 `performDrag` 签名规则。

模块自绘卡片使用物理尺寸。`ShareWorkspace` 在 LOCATION/DROP 更新已认证会话当前箭头偏移与声明半宽，扩展透明接收窗时只调整尺寸，不销毁活跃窗口。整张卡片触及横向边缘后进入滚动候选区，仍保留短暂停留门槛。

`DragEvent` 坐标相对接收它的窗口，不一定是 `ShareWorkspace` 所在窗口。接收窗与分享栏分属不同窗口时，命中换算必须先经屏幕空间（接收窗与分享栏各自的 `getLocationOnScreen`）再减箭头偏移，不能直接相减。凡以屏幕绝对坐标定位的独立窗口（`ShareDragCatchment`、`ShareRailOverlay`）都必须同时关闭 insets 与 cutout 下推（`FLAG_LAYOUT_IN_SCREEN|FLAG_LAYOUT_NO_LIMITS`、`setFitInsetsTypes(0)`、`LAYOUT_IN_DISPLAY_CUTOUT_MODE_ALWAYS`），否则窗口原点被状态栏下推，命中带整体偏移，表现为箭头离图标还远就选中、贴近反而不选中。

`ContentDragMotion` 复用工作区指针观察器，以固定物理偏移命中上箭头。原生 DROP 保留目标与系统坐标，投回同来源时调用 `endDragLocked(false,false)` 取消。临时提取窗会记录已校验的实际来源窗口，各应用提取和可识别的原生全局文字、图片、文件拖曳共用同来源取消规则。原生载荷与授权沿用平台流程。会话关闭或到期后清理记录和预览。工作区宿主、分享覆盖窗和透明承接窗是独立投递目标。核对窗口类型、标题与 SystemUI 会话身份后，即使与内容来源窗同 UID 同包，也需放行系统 DROP。

拖曳悬停把小窗升为主窗时，按稳定的小窗任务身份保留 DROP 目标，并以预测的目标主区作为回退命中范围；提升尚未确认时只暂缓启动，确认后若原生拖放仍未接管则按小窗接收包投递。确认提升的拖曳会话立即释放过渡输入遮挡，让原生 DROP 有机会落到新主窗，不合成指针事件。同来源主窗或同应用小窗仍取消。

图片悬停提升完成而 DROP 仍由宿主或过渡承接窗报告时，系统层在 `reportDropWindow` 阶段把该次 DROP 转交给指针下同用户、可见、全屏模式的目标窗，必要时先补发 `DRAG_STARTED`，并保留原 `ClipData`、URI 授权和来源输入。只处理图片 MIME、已认证的宿主承接窗和非来源应用的主窗；目标窗口未进入可接收状态时保持原宿主回退。过渡输入窗只在当前图片拖曳已认领提升目标且落点在目标主区时接管未转发的 DROP，并沿用等待主窗就绪的投递路径。

标准「拖曳到一步」窗口记录自身实际收到的单指物理坐标，在模块自有拖曳载荷中传给系统层。原生入口只有在核对模块UID、可见来源窗口、已标记卡片及屏内有效触点后才使用它初始化首帧，并恢复自绘卡片的物理热点。不套用主窗应用缩放。其他应用不能仅靠伪装包名或附加相同字段走这条路径，选中文字和接收权限保持原样。

原生卡片适配识别11参数和13参数的 `performDrag`，以末尾参数定位坐标和载荷，未知签名保持系统原行为。通过既有来源窗口、全屏任务、用户及安全属性校验后，将首次传入的来源逻辑触点按当前显示缩放变换一次，卡片热点保持物理尺寸，使首次显示与后续原生 MOVE 使用同一坐标空间。无效变换不替换。首帧无移动、左右布局与 OEM 首次触摸时序仍需真机验证。普通文件使用原有 ClipDescription 标签绘制短卡，不读取文件正文、不改变 URI、顺序和授权。

## 分享入口、投递与图片搜索

顶栏投递携带具体分享组件，小窗投递限定接收包。已有小窗目标复用确认后的任务提升回调，仍须遵守场景与用户校验。媒体查询权限、外部 URI 转授、后台启动及侧栏实际 DROP 路由需要在对应 ROM 真机验证。当前系统拒绝转授时明确失败，不使用全局权限放宽。

`ShareActions` 仅包含固定内置操作，不导入 HyperCopy 代码、远程规则或可配置匹配规则。地图使用公开 `geo:` 查询，搜索使用 `ACTION_WEB_SEARCH`，翻译使用 `ACTION_TRANSLATE`。无处理应用时由已安装浏览器处理编码后的 HTTPS 地址。移除内置笔记与顶栏粘贴入口，笔记仍可使用应用提供的分享组件。图片编辑使用公开 Intent。图片搜索使用模块内部 `VisualSearchActivity`，固定必应网页及其网页图片上传表单，不再读取图片搜索应用配置。入口与图标查询在既有工作线程执行，不在位置回调中查询安装列表。

`ShareDelivery` 的一次性 Binder 回执只接受本用户模块 UID：系统接受 DROP 后保留交付会话，模块完成读取并成功启动接收页面后回执成功。失败返回模块拥有的 URI 或纯文字供重试。回执只证明接收页面启动，不证明用户最终发送。代次、工作区退出、60秒超时与锁屏取消后，迟到代理不得继续启动应用。外部读取能力继续由真实 DROP 委托，未读取成功的原始 URI 不长期保留。

会话入口经 `EditorPasteCompat` 的认证中继在系统进程查询应用公开的 sharing shortcuts，最多32项，仅当前用户、启用且导出接收组件。通过标准 `EXTRA_SHORTCUT_ID` 传递会话身份，不猜测聊天界面、读取联系人或增加来源应用作用域。应用未公开或系统不允许查询时只保留普通分享入口。原生多项文字／图片影子保持所有原始 ClipData 项、顺序与授权载荷，不将摘要替代正文。

图片搜索仅在显式投递后读取模块拥有的单张图片，最长800px、JPEG 90%。在工作线程准备有界编码后，通过 `VisualSearchForm` 构造固定必应 HTTPS multipart 表单，在内置WebView自动上传并显示结果。不再使用原生HTTP上传、结果标识解析或默认浏览器交接，也不把图片内容放进普通GET参数。顶部只有返回、重试，不增加“必应”标题、引擎选择或文件选择器。网页无JavaScript接口，禁用文件、内容URI访问及混合内容。离开销毁WebView和编码数据，迟到的编码结果不再加载。网页的实际结果仍待真机验收。

分享入口查询按整组载荷的共同 MIME 匹配，与实际发送 Intent 保持一致。纯文字多项仍合并为 ACTION_SEND，多个文件用 ACTION_SEND_MULTIPLE，不因单项类型可用就启用不兼容整组的入口。保留异步交付的窗口 detach 也必须移除描边、接收窗口和顶栏动画，不将 UI 生命周期与交付能力寿命绑定。拖曳启动失败立即释放自有影子。内容页换页和关闭释放所属缩略图及放大预览，异步迟到结果自行回收。

## 性能与诊断

开机预热由 LSPosed 的 SystemUI 入口触发，等待用户解锁与原生工厂就绪。`TaskViewWarmup` 默认准备两个未挂载 TaskView，按用户、工厂和资源配置复用；首次打开只按需加载快捷应用，回访用户才做后台 TaskView、TopBar 和壁纸预热。不添加工作区窗口、不启动应用、不创建真实应用任务、不开启心跳。首次使用后不补货，迟到回调和不兼容缓存释放。原生构造前持久化本次开机尝试，SystemUI 同一次开机重启后不重试，避免崩溃循环。第三方应用本身的冷启动不能通过预热空容器消除。

| --- | --- | --- |
| 已打开应用标记 | 合并任务切换等可见事件，突发请求 100ms 合并 | 正常刷新最多每秒一次；隐藏、锁屏、detach 停止 |
| 媒体状态 | 活跃会话与播放状态回调在 40 毫秒内合并 | 稳定后 60 秒看门狗；失败从 2 秒指数退避到 10 秒，Host 失效即停止 |
| 缩放租约 | 呼出与命令变化时发布 Binder 租约 | 确认后不再续写文件；5 分钟复检，Binder 死亡立即恢复稳态 |
| 小窗渲染 | 实际 bounds、密度与焦点决定 30/60fps 提示 | 手机不创建未使用的第四格；只回收视口下方空尾行；隐藏 60 秒归还 TaskView |
| 常规诊断 | 首次与变化时输出 | 相同文本 30 秒限频，最多缓存 128 项 |
侧栏空闲任务使用 30fps 刷新提示，焦点侧窗、TOP 与切换中的任务使用 60fps；提示随 TaskView 释放清除。手机布局跳过多余的保留格，滚动模式下只回收视口下方的空尾行，不移动或释放已占用任务。Binder 租约确认后，稳定期心跳与表面回退检查降到 60 秒，文件通道不再周期性续写。TaskView 预热只保留未领取的空视图；内存裁剪时释放全部预热视图、窗口上下文与构造引用，后续首次打开直接走按需创建。侧栏最多保留 12 行，达到上限后不再创建新的空追加行；布局按视口、密度、主窗方向和设备形态缓存，最多保留 8 项。媒体播放状态未变化时不重复重建控制状态，相同任务的查询和刷新只在事件或节流窗口到达时执行。调试视图导出同时输出场景状态、TaskView/占用行数量、运行计数和 Java 堆使用量。

相同稳态缩放文件只更新租约时间；周期心跳不能重复写 Settings 或广播。内容变化、动画或文件异常仍使用 AtomicFile。广播、设置与文件通道独立，不能因一个通道失败而抑制退出命令。一次性后台任务统一进入带计数诊断的进程内守护线程池；需要严格顺序的媒体读取、缓存写入和分享准备保留独立命名的单线程池，避免共享池破坏串行语义。所有临时工作线程允许 30 秒空闲超时，工作结束后退出，不长期驻留休眠线程。缩放设置优先由 `ContentObserver` 和双目录 `FileObserver` 唤醒；两个目录均安装观察器后，文件通道空闲时以 60 秒兜底，否则为 10 秒。进入、退出、动画、几何变化和恢复时保留 250 毫秒兜底。两个目录均有观察器且请求与已经应用的缩放一致时，稳定期检查间隔最长 5 秒，临近 15 秒租约失效时按截止时间提前检查。息屏取消已排队的 watchdog，亮屏立即检查；显示几何变化不重复触发相同屏幕状态。工作区恢复还需默认 Display 处于 `STATE_ON`，不能只依赖 `USER_PRESENT`。工作区首帧等待仅在启动阶段做有界 16ms 重试并随场景、锁屏取消；顶部任务就绪、退出确认等短轮询采用 16/32/64ms 封顶退避，避免空闲逐帧查询。工作区隐藏 60 秒后释放仍保留的真实任务绑定，5 分钟后释放非必要壁纸、预览和图标缓存；内存压力回调按级别清空缓存，唤醒后按需重建。桌面任务发布合并 50ms，避免任务事件突发时重复查询和广播。
错误与生命周期日志不被常规限频吞掉。日志不包含密钥、个人消息或凭据。真机功耗结论须区分模块开销与共享系统进程、媒体播放、USB 调试的影响。

壁纸模糊先缩到三分之一尺寸，再以滑动窗口执行三轮横纵盒式模糊，复用像素缓冲以避免重复邻域求和和逐轮分配。开机壁纸缓存包含完成材质处理的底图和小尺寸圆井模糊图。工作区首次创建时，加载线程优先读取模块保存的背景图片。使用系统壁纸时转移这两个现成位图的所有权，未命中再异步获取。主线程不新增截图或模糊计算，使用后不补货，不新增隐藏渲染、真实应用启动或心跳。手势指定的本次主窗方向优先于已保存的位置，保留场景恢复也遵守这一规则。

工作区自定义图片由模块设置页通过系统选择器导入，缩小后原子写入模块私有目录。设置提供者只向同用户 SystemUI 开放背景文件的只读访问。图片与系统壁纸共用裁切、墨香玻璃和圆井模糊链路。变更通过内容观察者刷新，活动过渡完成后再替换底图。失败采用封顶指数退避，锁屏和隐藏时不排队重试，恢复后重新加载。

离线排查采用 `OneStepLiteShare` 日志标签，仅记录阶段及枚举状态码，不记录正文、包名、文件名、URI、凭证或图片。每进程内存环形记录最多64条，常规相同状态30秒限频。失败、拒绝和超时保留事件。模块 Provider 的 `share_diagnostics` 仅向原有鉴权宿主返回模块进程摘要。跨进程分析需合并同标签设备日志。原生输入交接仅记录阶段和枚举结果。日志只能定位提取、指针交接、复制或目标读取阶段，不能证明某个应用所有内容均可提取或目标最终发送成功。

## 构建验证与正式发布

本地与 CI 执行同一套 `:app:lintRelease :app:stageRelease` 和 `test.ps1`，包校验只用 `tools/assert_module_apk.py`。发布构建压缩 DEX，ARM64 原生库保持无压缩并页对齐。新增生产依赖逐个补入受影响套件的 javac 源列表，并核对 `checks=` 的变化。

`version.json` 是版本信息的唯一来源。发布版本码递增，签名私钥留在本地忽略目录或仓库 Secrets。正式 tag 必须生成签名 APK 和 SHA-256 校验文件。发布前确认源码、tag、CI 产物与 Release 指向同一个提交，真机验证范围如实记录。

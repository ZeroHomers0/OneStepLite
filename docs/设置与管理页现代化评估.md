# 设置与管理页现代化评估

评估范围：`SettingsActivity`、`WorkspaceSettingsPage`、`ShortcutManagementPage`、`ShortcutSettingsContent` 与 `PinnedAppEditor`。目标是保持 HyperOS 系统设置入口的一致观感，不在本轮引入独立设计语言或重型 UI 依赖。

## 现有基础

- 页面复用系统 Settings 的颜色、尺寸和单选/开关 Drawable；深浅色、字体缩放和大屏最大宽度已有统一入口。
- Activity 使用边到边 Insets、预测返回、主题切换重建和状态恢复；管理页预取数据，300ms 后才显示加载提示，并对迟到回调做代次隔离。
- 卡片、选择行、搜索、拖拽排序和行尾开关已经覆盖主要任务，没有必须迁移 Compose 或 Material 组件的功能缺口。

## 本轮必要改造

1. 设置开关行增加完整的标题、说明和开关状态无障碍描述，状态变化同步更新。
2. 菜单行报告“标题，当前摘要”，避免 TalkBack 只读到可见子标题。
3. 快捷应用和分享入口允许点击整行切换行尾开关，并为不可用入口报告原因与视觉弱化状态。
4. 管理页加载与失败提示标记为礼貌级实时区域，等待超过 300ms 时不会静默。
5. 继续保留现有 HyperOS 卡片、16dp 预览圆角、20dp 页面边距和 640dp 大屏内容上限，不重复实现第二套视觉系统。

## 未采用项

- **引入 Material Components / Compose**：会增加 APK、主题桥接和与系统 Settings 资源不一致的风险，当前收益不足。
- **改用独立 XML 布局体系**：现有页面以运行时主题、系统资源探测和图示绘制为主，迁移动态部分会扩大回归面。
- **增加首页搜索**：当前设置项数量有限且按外观、顶栏、分享、窗口、横屏、锁屏分组；先保证分组与无障碍语义，等真机验证出现明确查找成本后再评估。

## 验收

离线验证覆盖字符串、布局选择逻辑和架构边界；深浅色、大字体、TalkBack、折叠屏/平板宽度及管理页加载失败仍需 HyperOS 真机或模拟器界面验收。

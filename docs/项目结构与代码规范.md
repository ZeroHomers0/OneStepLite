# 项目结构与代码规范

本文是 OneStepLite 的工程约定：目录职责、分层边界、命名与代码风格，以及改动时必须满足的等价性要求。新增代码前先读这一篇，再动手。

## 1. 项目定位

OneStepLite 是一个 **LSPosed 模块**，不是普通应用。它没有桌面图标，通过 Xposed 钩子注入三个系统进程，在 SystemUI 进程内创建自己的工作区窗口：

| 进程 | 包名 | 注入内容 |
| --- | --- | --- |
| 系统框架 | `android` | 任务与窗口管理、主窗缩放、原生自由窗口、输入适配 |
| 系统界面 | `com.android.systemui` | 工作区窗口、标题栏、小窗、视频接入、状态栏协作 |
| 设置 | `com.android.settings` | 仅在系统设置首页插入 OneStepLite 入口 |
| 输入法（可选） | `com.xiaomi.type` | 仅横屏自动悬浮键盘策略 |

入口类固定为 `io.github.zerohomers0.onesteplite.HostEntry`，由 `app/src/main/assets/xposed_init` 声明，`HostEntry.handleLoadPackage` 按包名分派。

根目录只保留 5 个文件，因为它们被外部按固定路径或固定类名引用：

- `HostEntry.java` —— `xposed_init` 与 `tools/assert_module_apk.py` 按全名校验。
- `WorkspaceHost.java` —— 工作区宿主，被大量 `tools/*/run.py` 按文件名切片。
- `WorkspaceLayout.java` —— 纯几何，被单测直接引用。
- `SettingsActivity.java`、`WorkspaceSettingsProvider.java` —— `AndroidManifest.xml` 用相对类名声明。

### 分层边界

```
policy/            纯函数判定，不碰 Android API，不持有状态
   ↓
core/              常量、枚举、共享小工具
   ↓
platform/          系统接口兼容层，唯一允许大量反射的位置
   ↓
功能目录            swap/ top/ side/ video/ lock/ ime/ input/ ...
   ↓
WorkspaceHost      组装视图与生命周期
   ↓
HostEntry          进程入口与钩子安装
```

规则：

1. **`policy/` 不得 import `android.*`**，也不得持有可变静态状态——它是离线测试的主要抓手。需要 `WindowManager.LayoutParams`、`View` 常量这类平台类型的判定，放到 `platform/` 下同名的 `*Policy` 里（如 `platform/HostWindowPolicy`、`platform/SystemBarVisibilityPolicy`）。
2. **反射集中在 `platform/`**。功能目录需要系统私有接口时，通过 `platform/` 暴露的方法调用，不要就地写 `XposedHelpers.findClass`。
3. **`core/` 不放业务逻辑**，只放被两个以上目录使用的常量、枚举与纯工具。
4. **视图与逻辑分离**：`*Pane`、`*Rail`、`*Bar`、`*Preview`、`*Diagram` 只负责绘制与触摸，判定交给 `policy/` 或同目录的策略类。
5. **`WorkspaceHost` 是组装层**，新增能力优先落到功能目录，避免继续堆进宿主。

## 4. 命名规范

### 类型

| 后缀 | 含义 | 例子 |
| --- | --- | --- |
| `Policy` | 纯判定，静态方法 | `NavigationPolicy`、`WideVideoPolicy` |
| `Host` | 生命周期与视图组装 | `WorkspaceHost` |
| `Bridge` | 跨进程/跨层转发 | `DesktopLaunchBridge`、`SwapOverlayBridge` |
| `Compat` | 系统版本差异适配 | `ShellCompat`、`WindowRootsCompat` |
| `Session` / `Lease` | 有明确起止的会话或租约 | `LiveSwapSession`、`SwapPanelLease` |
| `State` | 状态枚举或状态快照 | `SwapSessionState`、`TopTaskState` |
| `Trace` | 诊断记录 | `InputTrace`、`SwapTrace` |
| `Pane` / `Rail` / `Bar` / `Button` | 视图 | `TopTaskPane`、`QuickAppRail`、`TopBar` |
| `Geometry` / `Layout` | 纯几何计算 | `TopBarGeometry`、`WorkspaceLayout` |

**类型名不带项目名。** 项目名只出现在包名、`AndroidManifest`、资源名与用户可见文案里，不进入 Java 标识符。

### 成员

- 常量：`static final` + 全大写下划线，如 `CELL_COUNT`、`VIDEO_FULLSCREEN`。
- 字段：小驼峰，不加 `m` 前缀；布尔字段用 `is`/`has`/`can` 或形容词，如 `mainOnRight`、`choosing`。
- 方法：动词开头，如 `applyScaleTransform`、`reassertSideTaskViews`、`handoffPromotedTask`。
- 私有工具方法：不加 `do`/`handle` 之类空动词，直接说明动作。
- 枚举：常量全大写，类型名用单数名词，如 `SwapSessionState.RUNNING`。

### 资源与资产

| 类型 | 规则 | 例子 |
| --- | --- | --- |
| drawable | `ic_<用途>` | `ic_settings_onesteplite` |
| style | `Theme.OneStepLite.<页面>` | `Theme.OneStepLite.Settings` |
| 资产目录 | `assets/onesteplite/` | `assets/onesteplite/licenses/` |
| 原生库 | `libonesteplite_raw.so` | 由 `Android.mk` 的 `LOCAL_MODULE` 决定 |

## 5. 代码风格

- **缩进 4 空格，禁止 Tab**；文件以 LF 结尾，无行尾空格。
- **导入**：不使用通配符导入；按 `android.*` → `java.*` → `de.robv.*` → 其他 分组，组内按字母序。
- **大括号**：K&R 风格，`{` 不换行。
- **单行紧凑写法**是本项目既有风格，例如 `if(tx!=null)XposedHelpers.callMethod(tx,"apply");publish();`。修改既有文件时保持原风格，不要顺手重排；新文件优先可读性，但同一文件内保持一致。
- **方法长度**：单个方法控制在 100 行以内。超过时按「一件事」拆成同类的私有方法（如 `buildLayout` 拆成 `resolveMainSide`/`createRootView`/`watchSideViewport`/`createHostWindow`/`createTopBar`/`startWorkspaceHeartbeat`），不移动成员、不改可见性，因此不影响工具切片。
- **注释**：类型用一行 Javadoc 说明职责，如 `/** A clock, four fixed workspace actions, and an unmasked application rail. */`；复杂算法在方法内用行注释说明**为什么**，不复述代码。
- **日志**：统一走 `Log`/`XposedBridge.log`，tag 用 `Tags.PROBE`；日志文案英文，用户可见文案中文。
- **用户可见文案**：中文，术语统一为「主窗」「小窗」「工作区」「一步标题栏」「顶部横屏任务面」。

## 6. 构建与测试

### 构建

```bash
./gradlew :app:assembleDebug      # 调试包
./gradlew :app:lintRelease        # 静态检查（CI 也跑）
./gradlew :app:stageRelease       # 发行包 + 校验 + dist/ 校验和
```

版本号只有 `version.json` 一处：`app/build.gradle.kts` 用 `JsonSlurper` 读 `name`/`code`，`build.ps1` 读同一份文件并校验 `runtimeMarker`。改版本只改这一个文件。

Lint 分两层：`app/lint.xml` 关掉对 LSPosed 模块不适用的检查（`PrivateApi`、`MissingPermission`、`WrongConstant`、`ViewConstructor`、`ClickableViewAccessibility`、`IconLauncherShape`），`app/lint-baseline.xml` 记录其余历史问题。新增代码不得往基线里加条目；确认旧条目失效时用 `./gradlew :app:updateLintBaseline` 重新生成并检查 diff。

`stageRelease` 依赖链：`assembleRelease` → `verifyApk`（`tools/assert_module_apk.py`）→ `stageRelease`（复制到 `dist/` 并写 `SHA256SUMS.txt`）。

`gradle.properties` 里有三条不可删除的开关，它们保证产物与手工链路一致：

| 开关 | 作用 |
| --- | --- |
| `android.builtInKotlin=false` | 项目无 Kotlin 源码，禁止注入 Kotlin 标准库 |
| `kotlin.stdlib.default.dependency=false` | 同上，去掉隐式依赖 |
| `android.enableResourceOptimizations=false` | 保持资源文件名稳定，便于包校验与对比 |

### 测试

```bash
powershell -NoProfile -ExecutionPolicy Bypass -File ./test.ps1
```

`test.ps1` 自行编译生产源码，然后依次运行：

1. `tests/*.java` —— 51 个策略单测，纯 JVM，直接 `javac` + `java`。
2. `tools/*/run.py` —— 106 个生产方法回放套件：从真实源码中按文本切片取出方法体，套进最小 fixture 编译运行，验证真实实现而非复制品。
3. `tools/rotation-jvm/run.ps1` —— 窗口管理与旋转相关测试。

全部通过时输出 `All offline tests passed. Device behavior requires separate validation.`。**离线测试只证明逻辑等价，真机行为必须单独验证。**

### 等价性约束（重要）

`tools/` 的套件按**精确文本**从生产源码中切片方法体。因此：

1. **不要在被切片的方法里新增私有辅助方法**。切片只带走方法体，辅助方法不会跟过去，套件会编译失败。被切片的方法清单见各 `tools/*/run.py` 的 `source.index(...)` 调用。
2. **新增生产类若被某个套件编译到，必须把该类加入该套件的 javac 源文件列表**，逐个套件显式添加，不要写批量替换脚本。
3. **改动后必须重跑 `test.ps1` 并比对 `checks=` 计数**，计数变化要么是新增断言，要么是回归。
4. **`build.ps1` 是等价参考实现**，改动构建相关逻辑后应与 Gradle 产物交叉核对（入口类、Xposed 资产、许可文件、未压缩的 ARM64 原生库）。

## 7. 为什么所有源码共用一个包

历史上曾评估把源码拆成 `io.github.zerohomers0.onesteplite.<area>` 形式的真实子包，结论是**不可行**：

- 180 个类中，**0 个**能在不扩大可见性的前提下移动。
- 包私有耦合图是**一个连通分量**（3606 条边、180 个节点、0 个孤立点），全局最小割只隔离出 1 个类。
- 完整拆分需要约 126 处成员可见性放宽，且正则批量放宽会破坏声明语法。
- 会波及 74 个 `tools/` 套件与 12 个单测。

因此采用**只移动目录、保留包名**的方案：目录表达功能归属，包名保持单一，`tools/source_paths.py` 负责把 `src/'WorkspaceHost.java'` 解析到真实子目录。

## 8. 提交约定

- 一个提交只做一件事，提交信息用祈使句概括改动，例如 `Reuse the header's button arrays across measure and layout`。
- 提交前必须：`./gradlew :app:stageRelease` 通过、`test.ps1` 全绿、`git diff` 自查无调试残留。
- 不提交：`build/`、`dist/`、`.gradle/`、`local.properties`、签名私钥、设备日志、个人截图。
- 保留用户未提交的改动；提交、推送、发布分别按授权执行。

## 9. 过渡动画的归属

过渡逻辑按功能集中，宿主只组装任务和生命周期，不再另写工作区动画曲线。

| 类型 | 职责 |
| --- | --- |
| `TransitionSession` | 取消与当前场景检查；会话退役后，旧帧、旧回调不能再写入 |
| `WorkspaceTransition` | 工作区进入、退出的时间线、主窗几何和侧栏位移 |
| `WorkspaceMotionSpec` | SystemUI 与 WM 共用的曲线、时长和单调时钟起点 |
| `TopTaskTransition` | 顶栏收纳、显示、退出时的表面透明度；原生事务提交前补齐保护 |
| `TopTaskFrame` | 原生转场空闲、目标逻辑尺寸、窗口绘制同步及隐藏宿主帧的就绪检查 |
| `LiveSwapSession` | 保留已有真实任务交换与恢复流程 |
| `WorkspaceBackdrop` | 不参与主窗缩放的物理壁纸托底，以及退出后原生事务提交确认 |

同一动画起点不代表两个进程会在同一 SurfaceFlinger 帧提交。手机与平板都必须保留物理壁纸托底，不能靠微调曲线掩盖空洞。退出时只在 WM 恢复全屏的事务提交后释放托底；新场景会取消旧的释放请求。

侧栏加号、应用内容与 SurfaceView 使用同一份位移，滚动行的布局更新也必须保留该位移。壁纸底板保持屏幕坐标。RenderThread 负责 SurfaceView 父层的位置，不额外叠加第二次位移或缩放。

顶栏接入时先隐藏目标容器，直到最终尺寸与绘制同步通过，再进行一次淡入。Core/Shell 任务归属确认不能替代画面就绪确认。等待期间，原生打开与收尾事务也不得提前恢复目标透明度；失败时保持隐藏并将原任务交回系统。

原生小窗共存时，工作区遮罩位于最高可见原生小窗之上，主窗透明洞仍透出原生内容；遮罩仅覆盖越出主窗的画面，不修改 OEM 任务的变换、关闭或停靠手势。离开工作区、停靠或原生任务消失时恢复原始层级。

快捷应用选择框通过 `ModalIslandLease` 暂借灵动岛根视图的显示状态，选择框关闭或脱离窗口时恢复；不修改导航、媒体会话和通知数据。弹窗期间新增或重建的灵动岛根也受同一租约约束。

### 呈现与诊断资源归属

- `TopPresentationController` 统一视频准入回调、手动任务退出控件及视频刷新与隐私释放；任务身份和原生事务仍由宿主处理。
- `WorkspaceChrome` 只组装顶栏层级、裁剪容器和侧栏底板，不持有任务或过渡会话。
- `MirrorExperiment` 持有实验浮层、镜像与原任务的临时隐藏状态，替换实验时撤销旧计时器。
- `LeashExperiment` 持有实验动画、计时恢复和临时底板隐藏，取消后旧动画回调不得再次写入；正式任务变换继续走宿主原路径。

这些类通过窄回调连接宿主，不扩大宿主字段可见性。

### 侧栏、交接、锁屏和系统钩子的边界

| 组件 | 所有权与边界 |
| --- | --- |
| `SideRowOrder` | 侧栏逻辑行序、可滚动范围与物理位置映射，保留原 Slot 对象 |
| `SideScrollMotion` | 吸附、惯性与压缩动画回调，取消时清理原根视图的帧队列 |
| `TaskReturnCoordinator` | 返回原生主窗的观察、有限重试与一次性收尾；宿主执行原生事务和槽位更新 |
| `TaskHandoffPolicy.bindingCurrent` | 收纳、交换与返回共用场景、绑定代次、任务 ID 和 token 校验 |
| `WindowPrivacy` | 锁屏窗口透明度与输入标志的保存、恢复和失败回滚 |
| `WorkspaceZoomCommands` | 工作区与实时交换共享命令代次，延迟稳态写入须仍属于当前代次与场景 |
| `ZoomTransport` | 广播、Settings 与原子文件发布；一个通道失败不阻断其他通道 |
| `WorkspaceScreenObserver` | 屏幕、解锁和导航广播注册与路由 |
| `WorkspaceWindowHooks` | 主窗动画边界、最近任务壁纸合成钩子 |
| `BackGestureDiagnostics` | 原生返回输入观察，不接管原生手势 |

宿主继续保留任务身份、布局快照和原生事务的装配；组件通过回调读取当前场景，不缓存可替换的任务对象。已有 `WorkspaceTransition`、`UnlockHandoff`、`RetainedWindow` 与 `LiveSwapSession` 继续负责其原有的提交和所有权门槛，不另建平行流程。

离线回放验证逻辑与取消边界；HyperOS 黑边、闪白、视频触摸、旋转和锁屏后的真实合成效果仍须兼容设备验收。普通 Android 模拟器不作为这些项目的验收依据。

### 日夜外观、设置同步与解锁收尾

三组设置图示共用卡片结构、206dp 图高、配色与点击区域。设置标题和说明分别使用 16sp、12sp，开关前保留 16dp 文本间距。手势页显示真实保存项，不用回退项替代选中项。配置观察与定向唤醒都只触发提供器重读，旧读取结果按请求代次丢弃。

`topWallpaperTint` 在日间保持透明，夜间覆盖半透明深色；宿主配置变化时更新底板与文字对比色。

原生小窗根层的相对层级不能只加一：客户端子层也参与同一层级遍历。只对精确识别的 SystemUI 自有工作区窗口使用保留的高层级区间，原生任务的变换和父节点保持不动。遍历关系可参照 [AOSP Layer::traverseInZOrder](https://android.googlesource.com/platform/frameworks/native/+/ab2a0e6de5f9c4e7b7db695d4dc2ac15fb82248e/services/surfaceflinger/Layer.cpp)。

解锁释放协议携带预期几何及显式工作区呈现标记；只有 Host 硬件帧提交后才能发送工作区标记。成功时在解除主窗遮挡前补齐保留几何，不因原生可见性缓存迟到而恢复物理全屏；失败、超时或退出走物理全屏。较新的不同缩放命令可否决旧解锁几何，防止快速退出被晚到回调覆盖。

解锁的原生 start/finish 事务可能在锁屏全屏时提前生成，随后晚于 Host 几何确认提交。`UnlockGeometryReplay` 在确认时保存 WM 几何事务的非消耗副本，按事务身份跟随原生 merge，在标记的解锁事务实际 apply 前补齐同一场景、同一几何的主窗变换。普通事务不处理，进入新锁屏或退出时释放副本；避免仅靠事后续租修复大图标截断。

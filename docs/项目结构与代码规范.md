# 项目结构与代码规范

OneStepLite 是运行在 Android 上的 LSPosed 模块。界面层组装工作区、设置和内容面板，系统层负责任务、窗口、Surface 与原生输入协作。用户操作见 [README](../README.md)，视觉与输入规则见 [界面与交互规范](界面与交互规范.md)，原生约束见 [系统与平台规范](系统与平台规范.md)。

## 1. 仓库入口

| 路径 | 职责 |
| --- | --- |
| `app/` | 唯一 Gradle 模块，包含 Java 源码、资源、Xposed 入口、许可资源与原生实现 |
| `app/src/main/cpp/` | 原生输入映射及 NDK 构建 |
| `tests/` | 纯 JVM 策略测试 |
| `tools/` | 生产代码回放、APK 校验与构建身份生成 |
| `docs/`、`docs/assets/` | 工程规范及用户文档引用的应用示意图 |
| `version.json` | 版本名、版本码和运行标记的唯一来源 |
| `test.ps1`、`build.ps1` | 离线测试入口及参考构建链路 |

应用进程和系统注入过程的边界见 [系统与平台规范](系统与平台规范.md#进程与分层)。

## 2. 宿主与入口

Java 源码位于 `app/src/main/java/io/github/zerohomers0/onesteplite/`，物理目录按 NeXtep 的领域职责划分；所有文件仍声明同一个包名。

| 类型 | 所在目录 | 职责 |
| --- | --- | --- |
| `HostEntry` | `xposed/` | Xposed 入口，按进程安装钩子，与 `xposed_init` 和 APK 校验约定一致 |
| `WorkspaceHost` | `systemui/` | 组装工作区场景、真实任务身份、输入和呈现组件 |
| `WorkspaceLayout` | `workspace/` | 工作区几何，供生产代码和纯 JVM 测试共同使用 |
| `SettingsActivity`、`WorkspaceSettingsProvider` | `config/` | 设置页和经身份校验的配置入口，保留 Manifest 声明的类型名 |

## 3. 功能目录

| 目录 | 职责 |
| --- | --- |
| `xposed/` | LSPosed 入口和进程分派 |
| `systemserver/` | system_server Hook、平台兼容、旋转、缩放与原生窗口协作 |
| `systemui/` | SystemUI 工作区、顶栏、输入法、锁屏、状态栏、视频和壁纸呈现 |
| `display/` | 小窗行序、侧栏手势、拖动换位、实时任务交接和过渡 |
| `task/` | 任务身份、槽位、交接票据和恢复协调器 |
| `workspace/` | 工作区几何、布局、过渡、启动预热和视觉策略 |
| `config/` | 设置页、设置存储、运行选项和快捷设置内容 |
| `apps/` | 快捷应用、应用栏、内容面板与分享流程 |
| `launcher/` | 启动路由、最近任务和桌面协作 |
| `framework/` | Shell、窗口、同步和跨组件基础兼容层，反射兼容位于其 `platform/` 子目录 |
| `trigger/` | 状态栏、角落、底部和四指入口手势 |
| `logging/`、`monitoring/` | 日志、运行计数、调试快照和生命周期诊断 |
| `safety/`、`multiapp/` | 隐私/入口保护与多用户任务边界 |
| `icons/` | 通用图标、轮廓和按钮资源组件 |
| `policy/`、`core/` | 无 Android 依赖的纯策略，以及跨功能常量与通用工具 |

- `WorkspaceHost` 保留场景编排与跨组件事务，显示采样、壁纸、侧栏行序、格子表面和顶栏/侧栏裁剪分别由 `WorkspaceDisplayController`、`WorkspaceWallpaperController`、`WorkspaceSideRowController`、`WorkspaceCellSurfaceController`、`WorkspaceChromeController`、`WorkspaceExitController`、`WorkspaceResumeController`、`WorkspaceLaunchController` 持有；其中退出控制器单独持有隐藏保留任务的 60 秒回收定时器。控制器只跨同一个领域边界协作，新增能力先扩展现有控制器，不继续堆入宿主。
- `SideRowOrder` 映射逻辑行和物理槽位，保留原有 `Slot` 对象。实时任务交接复用 `LiveSwapSession`，视图位置过渡复用 `CellMotion`、`SideScrollMotion` 或 `WorkspaceTransition`。原生提交和状态恢复门槛见系统规范。
- `TransitionSession` 封装取消和场景有效性。`WorkspaceMotionSpec` 提供跨进程共享的时间参数。`TopTaskFrame` 校验顶部任务就绪。`WorkspaceBackdrop` 持有物理屏幕坐标的壁纸托底。
- `MirrorExperiment` 和 `LeashExperiment` 持有各自的实验窗口、计时和临时表面。停止实验必须撤销其资源，生产任务继续走正式交接流程。

## 5. 命名与代码风格

- 类型名不带项目名。项目名可用于包名、Manifest、资源名和用户文案。`Policy` 表示纯判定，`Compat` 表示平台兼容，`Session` 或 `Lease` 表示有起止的会话或资源租约。
- 方法和字段使用小驼峰，方法名描述动作，布尔字段用 `is`、`has`、`can` 或形容词。常量用大写下划线。文件以 LF 结尾，缩进四空格，导入显式列出。
- 单方法最多 100 行，在原类内按职责拆分。保留普通类和成员的可见性，并遵守下文的切片约束。宿主入口类型的结构由架构检查保护。
- 常规日志走项目日志标签，说明事件和原因。界面统一使用「主窗」「小窗」「工作区」「顶栏」。许可证、设备日志、签名凭据和个人资料按其独立边界处理。
- README 使用应用当前绘制代码导出的示意图。新增或清理图片时核对文档引用、Manifest 与 Android 资源别名。

## 6. 构建与测试

使用 JDK 21、Android SDK、Python 3。SDK、构建工具和 NDK 版本由 [Gradle 配置](../app/build.gradle.kts) 决定。

```powershell
./gradlew :app:lintRelease :app:stageRelease
./test.ps1
```

- `stageRelease` 由 `assembleRelease`、`verifyApk` 和产物阶段组成。APK 校验只用 `tools/assert_module_apk.py`，检查入口、资产、许可证、DEX 和 ARM64 原生库。产物及 SHA-256 文件在 `dist/`。
- `build.ps1` 维护等价参考链路。两条链路都读取 `version.json`，通过 `tools/generate_build_identity.py` 生成运行标记。Gradle 配置缓存跟踪版本文件。CI 和本地执行同套命令。
- Lint 配置只关闭 LSPosed 不适用项，基线记录历史问题。新增问题不得加入基线。确认历史问题失效时使用 `./gradlew :app:updateLintBaseline`，并检查基线差异。
- `tools/` 套件从生产源码切片。被切片的方法内不要新调私有辅助方法。新增生产类若被测试编译，逐个加入受影响套件的 javac 源列表。重跑全套检查，核对 `checks=` 变化来自有意的新增或调整。
- 离线测试验证策略、所有权、取消和事务顺序。Surface 合成、输入路由和 OEM 兼容性仍需匹配 ROM 的真机。

## 7. 为什么所有源码共用一个包

生产源码使用 `io.github.zerohomers0.onesteplite`。目录按功能划分，包私有成员供跨功能组件和本地切片夹具共用。历史拆包评估发现大量成员需要扩大可见性，现有架构继续保持单包。测试用 `tools/source_paths.py` 定位物理源码文件。

## 8. 提交与发布

保留用户已有改动，按授权分别执行提交、推送与发布。提交前通过构建和离线测试，并核对差异与检查计数。临时脚本与验证产物放在 `build/`。`build/`、`dist/`、`.gradle/`、`local.properties`、签名私钥、设备日志及个人截图均不提交。

正式发布递增版本码、使用仓库签名 CI，并按系统规范核对标签、签名和产物。
